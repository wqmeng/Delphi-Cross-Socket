# Issue #218 HTTP 客户端空请求解析修复

状态：已完成

## 目标与范围

修复普通 HTTP 响应完成或请求超时后，接收端继续解析数据而解引用空的 `FRequestObj` 的问题；禁止同批尾部数据被回调启动的下一请求接收。保留临时响应、WebSocket 升级、EOF 定界、早响应及独立发送回调语义。

仅修改 `Net/Net.CrossHttpClient.pas` 和相关回归测试、说明。保留工作区已有的 `Net.CrossHttpParams.pas`、`Utils.Utils.pas` 及诊断文档改动。不修改通用 Parser、Socket/TLS 层、公共接口布局或引入重试。

- [x] 在请求锁内同时检查活动请求和登记接收保护；无请求或终态数据不进入 Parser。

## 验证方式

组件测试不靠 Sleep 争抢时序：捕获解析异常，检查正文、回调次数、连接闭态/复用资格、pending 数和发送保活；覆盖同包尾部、空闲尾部、回调内下一请求、早响应晚发送完成、超时后接收和 EOF。超时清理到 Close 之间的窗口通过仅测试编译宏下的门控验证。

真实 TCP 测试发送合法定长响应后追加 CRLF/额外响应，验证已有合法响应只完成一次、连接不复用、后续请求从新连接正常完成；正常 keep-alive 对照保持复用。验证命令沿用相邻测试的工具链和搜索路径，产物位于忽略的 bin/lib，保存源码与二进制哈希。

相邻测试覆盖 HEAD、临时响应、响应定界/失败、超时候选重验、WebSocket 握手及首帧。测试通过前不声称修复完成。

## 设计边界

普通最终响应可用待完成标志在连接内收尾，无须修改 Parser API。失败/超时终态优先于待发布成功，避免重入 Close 后补发成功。已经完整验证的响应可保留成功，额外数据使连接失去复用资格。实际 Close 和业务回调在请求锁外执行。请求占用的释放仍只在发送及响应都结束后发生一次。
